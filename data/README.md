# Data directory — MoveInSync review analysis

This directory stores the review dataset and analysis artifacts generated by `MoveInSync_Review_Collection_and_Analysis.ipynb`.

## Files

| File | Purpose |
|---|---|
| `MoveInSync_Public_Reviews_Combined.csv` | Deduplicated collected reviews with rating, date, text, metadata and provisional theme tags. |
| `collection_metadata.json` | Collection timestamps, request counts, errors, actual sample size and limitations. |
| `Findings_Summary.json` | Compact summary of sample counts and listing-level context fields, if available. |
| `low_star_theme_by_month.csv` | Multi-label low-star theme counts by month. |
| `Manual_Review_Audit_Template.csv` | Sample for manually checking rule-based theme labels. |
| `Public_Web_Source_Log.csv` | Public URLs, retrieval status and text extracts, if stored in this folder. |

Filenames may vary slightly by notebook version. Keep actual generated filenames and update this table if they change.

## Recorded collection run

- 1 star: 259
- 2 stars: 33
- 3 stars: 26
- 4 stars: 42
- 5 stars: 640

There were 292 one- or two-star reviews in the collected sample.

The separate requests for additional one-star and two-star reviews **failed** because the notebook passed `filter_score`, which was unsupported by the installed package version. The error suggested `filter_score_with`. Therefore, do not describe the 292 records as an additional targeted sample: they were present in the all-rating sample.

The listing metadata did not capture the current overall score, total ratings, or last-updated date in that run. These values must be verified separately before being reported.

## Regenerate the data

1. Open the notebook in Google Colab.
2. Fix and test the targeted star-rating filter against the installed `google-play-scraper` version.
3. Run the notebook from top to bottom.
4. Confirm the listing snapshot request status.
5. Check row counts, duplicate IDs, rating values, date range and source URLs.
6. Inspect `collection_metadata.json` for failures or shortfalls.
7. Open `Manual_Review_Audit_Template.csv` and verify a mix of themes and ratings.
8. Rebuild charts from the verified CSV and update the report's figures and counts.

Collection targets are ceilings, not guarantees. The third-party scraper may return fewer records or be blocked. The review sample is a convenience sample of recent accessible reviews, not a representative sample of all historical reviews or all employees.

## Interpretation rules

- Use listing-level score and total ratings for overall Play Store context; use the collected CSV for sample-level analysis.
- A sample's star distribution is not the app's full Play Store distribution.
- Theme labels are keyword-based, multi-label suggestions. One review may contribute to multiple themes.
- `other_unclear` is a prompt for manual review and taxonomy improvement, not a confirmed product issue.
- Monthly review counts are not complaint rates; there is no denominator for trips, active users or total reviews.
- A public complaint is evidence of a reported experience, not proof of its technical or operational cause.
- Public Help Center pages show documented support topics, not how prevalent those issues are.

## Privacy and repository guidance

Review text can contain personal details even when posted publicly. Keep raw data access limited, avoid including reviewer identifiers, and do not publish more content than necessary to substantiate the analysis. Check platform terms and organizational rules before sharing collected records.

If the data has not been regenerated and verified, do not replace recorded counts with assumptions. Keep collection metadata alongside the exact CSV it describes.
